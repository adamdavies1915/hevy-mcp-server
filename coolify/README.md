# Coolify recipe

`hevy-mcp-server.yaml` is a [Coolify](https://coolify.io) service template. It
deploys the published image from GHCR with a persistent volume, a generated
encryption key, and a domain from your Coolify wildcard.

## Deploy it on your own Coolify

Coolify can run any compose file, so you do not need the template upstreamed to
use it:

1. In your project, choose **+ New** → **Docker Compose Empty**
2. Paste the contents of `hevy-mcp-server.yaml`
3. Set the required environment variables (below), then deploy

## Required configuration

| Variable | Required | Notes |
|---|---|---|
| `GITHUB_CLIENT_ID` | yes | From your GitHub OAuth App |
| `GITHUB_CLIENT_SECRET` | yes | From your GitHub OAuth App |
| `HEVY_API_KEY` | no | Single-user mode; requires the allowlist below |
| `ALLOWED_GITHUB_USERS` | with `HEVY_API_KEY` | Comma-separated GitHub logins |

`COOKIE_ENCRYPTION_KEY` is generated by Coolify from `SERVICE_HEX_64_COOKIEKEY`
— the server requires exactly 64 hex characters, which is what that magic
variable produces.

### The domain comes first

The GitHub OAuth App needs a callback URL, and that URL depends on the domain
Coolify assigns. So:

1. Deploy once. The container will exit with
   `Missing required environment variable GITHUB_CLIENT_ID` — that is expected.
2. Copy the domain Coolify assigned.
3. Create a GitHub OAuth App at <https://github.com/settings/developers> with
   Homepage `https://<domain>` and callback `https://<domain>/callback`.
4. Set the two variables and redeploy.

## Persistence

`/data` holds the SQLite database with OAuth sessions and encrypted Hevy API
keys. The template declares a named volume for it. Remove that volume and every
redeploy signs all users out.

## Submitting it upstream

To get this into Coolify's one-click service list, open a PR against
[coollabsio/coolify](https://github.com/coollabsio/coolify):

1. Copy `hevy-mcp-server.yaml` to `templates/compose/hevy-mcp-server.yaml`
2. Add a logo at `public/svgs/hevy.svg` to match the `# logo:` header
3. Run `php artisan services:generate` to regenerate
   `templates/service-templates.json`

The image must be publicly readable first — see
`.github/workflows/publish-image.yml`, and make the GHCR package public in the
repository's package settings after the first successful run.
